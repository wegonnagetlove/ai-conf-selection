# Отбор докладов: «Технологии ИИ в науке и образовании» 2026

Сайт для экспертного отбора докладов IV Международной молодежной научной конференции «Технологии ИИ в науке и образовании» (conf.msu.ru, мероприятие 10771). Доклады разложены по 13 секциям; эксперт входит по личному коду, отмечает доклады («Выбрать», «Под вопросом», «Не подходит»), оставляет комментарий и видит отметки коллег. В разделе «Итоги отбора» собрана сводка по секциям с копированием таблицы.

Развёрнут на TatNet: https://ai-conf-selection.tatnet.app

## Кураторы и оператор

Система частично дублирует портал «Ломоносов», поэтому на портале статусы меняет только оператор, и только один раз, по итогам отбора. Порядок работы (согласован 17.11.2026):

1. **Эксперты** ставят отметки «Выбрать», «Под вопросом», «Не подходит» с комментарием.
2. **Куратор секции** проверяет заявки и на каждой карточке выбирает решение. Список решений совпадает со статусами на портале: «Новая» (решение не принято), «На рассмотрении», «Принята: устный доклад (очно)», «Принята: устный доклад (онлайн)», «Принята: постер (только для очных)», «Принята: очный участник-слушатель», «Принята: онлайн участник-слушатель», «Отклонена». Если тезисы оформлены неправильно, куратор отмечает «Дать автору время на доработку (до 01.12)» и пишет, что исправить: этот текст попадает в столбец «Уведомление автору». Исправленные файлы после 01.12 смотрят уже на портале.
3. **До 21–22 ноября** куратор в «Итогах отбора» копирует «Таблицу статусов для оператора» по своей секции и отправляет оператору.
4. **Оператор** проверяет сверку (нет спорных ситуаций, всё формально подходит, у автора с двумя докладами один статус) и **22 ноября** вручную меняет статусы на портале, при необходимости правя текст уведомления.
5. Оператор скачивает «Программы секций» (архив из 13 файлов Word по шаблону из памятки) и рассылает кураторам в чат на проверку. Общая программа (кнопка «Общая программа (Word)») **23 ноября** публикуется на портале как предварительная.
6. Дальнейшие изменения кураторы вносят на портале и в программу сами, оператор координирует и собирает общий файл.

В панели куратора задаются время, зал, модератор, эксперты и порядок докладов; кнопка «Скачать программу секции (Word)» собирает программу секции.

На карточках сайт сам помечает то, что проверяется до отбора: возраст старше 35 на 08.12.2026, школьник, постер при дистанционном участии, нет файла тезисов, больше 2 страниц (объём в знаках не проверяется), второй доклад автора в другой секции. Фильтр «Больше 2 страниц» показывает такие доклады отдельно. Решение по заявке, где куратор или оператор сам автор или соавтор, сервер не принимает: его ставит другой член оргкомитета.

В сверке для каждой заявки указаны соавторы: их заявкам на портале ставится тот же статус. Участники-слушатели без доклада в систему не попадают, их статусы оператор ставит на портале сам.

Решения, сохранённые до 17.11 со статусом «Требуется доработка», при загрузке автоматически переводятся в «На рассмотрении» с отметкой о доработке.

Куратора задают в `EXPERTS` префиксом с номерами секций: `#6 Иванова А.А.=код` или `#5,6 Иванова А.А.=код`. Помощник куратора: `+11 Иванова А.А.=код` (оценивает доклады секции 11, решений не принимает). Наблюдатель: `!#4 Иванова А.А.=код` (только просмотр секции 4). Администратор (`*`) видит все секции и может принимать решения по любой из них.

Каждый, кроме администратора, видит только свои секции: сервер не отдаёт доклады, PDF тезисов, отметки, решения и программы других секций. Код без префикса секций не открывает ни одной секции.

## Устройство

- `server.js`: Node.js сервер без внешних зависимостей. Отдаёт страницы и данные только после входа, хранит отметки экспертов и решения кураторов.
- `program.js`: сборка программы секций в Word (.docx) без внешних библиотек.
- `site/index.html`, `site/login.html`: интерфейс.
- `site/data/sections.json`: доклады по секциям (без телефонов, адресов почты и дат рождения). Наружу отдаётся только через `/api/sections` после входа.
- `scripts/parse.py`, `scripts/build.py`: сборка `sections.json` из выгрузки заявок conf.msu.ru. Дата рождения в файл не попадает, пишется только признак `over35`.

Отметки экспертов, решения кураторов, порядок докладов и данные секций хранятся в файле `marks.json` в отдельной ветке `marks` этого репозитория: сервер пишет их через GitHub API не чаще раза в две секунды. Ветка `main` при этом не меняется, поэтому лишних сборок нет, а вся история отметок видна в коммитах ветки `marks`.

## Переменные окружения (TatNet: «Переменные окружения»)

| Имя | Значение | Секрет |
|---|---|---|
| `EXPERTS` | эксперты и коды входа: `*Петрухина П.И.=код; Иванов И.И.=код2; …` (разделитель `;`, код не короче 4 символов, строка без имени считается кодом администратора, `*` отмечает администратора) | да |
| `SESSION_SECRET` | длинная случайная строка для подписи сессий | да |
| `GITHUB_TOKEN` | fine-grained токен GitHub только на этот репозиторий с правом Contents: Read and write | да |

Без `GITHUB_TOKEN` сайт работает, но отметки живут только в памяти и пропадают при перезапуске; об этом предупреждает надпись на странице.

Добавить эксперта: дописать его в `EXPERTS`. Отозвать доступ: удалить строку. Сменить `SESSION_SECRET`: выйдут все.

## Обновление списка заявок

```bash
python3 scripts/parse.py путь/к/request_list_event_10771_….xls
python3 scripts/build.py
python3 scripts/attach_pdfs.py путь/к/архиву.zip   # если есть новые тезисы: rows.json нужен для точного сопоставления файлов
rm rows.json
git commit -am "Обновлён список заявок" && git push
```

Отметки привязаны к ключу `<номер заявки>-<1|2>` и при обновлении сохраняются. Исходная выгрузка в репозиторий не добавляется (`.gitignore`), так как содержит контактные данные участников.

## PDF тезисов

Файлы лежат в `files/<номер заявки>-<1|2>.pdf` (приватный репозиторий) и отдаются по адресу `/files/…pdf` только после входа. В карточке доклада появляется кнопка «Открыть тезисы (PDF)» и число страниц.

Как добавить:
1. На confhub, на странице заявок мероприятия 10771, сформировать и скачать архив файлов заявок.
2. `python3 scripts/attach_pdfs.py путь/к/архиву.zip` (или папка). Номер заявки берётся из пути и имени файла; если у автора два доклада, файл подбирается по совпадению названия с текстом PDF. Word-файлы переводятся в PDF.
3. Файлы без номера заявки скрипт перечислит: их можно разложить вручную, `--map 1815415-1=файл.pdf`.
4. `git add files site/data/sections.json && git commit -m "PDF тезисов" && git push`.
